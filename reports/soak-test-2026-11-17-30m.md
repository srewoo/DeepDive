# Soak Test: 30m (memory + stability), new-tab live scene and game

_Method: Claude Code Game Studios `/soak-test 30m all`. 17 November 2026. The skill expects a human tester; here the play was automated, so the balance/fatigue focus is NOT ASSESSED (see below)._

## Pre-Session Setup
- Build: extension 1.1.0 from `extension/`, served with the extension's script policy, in Chrome (Playwright) on Apple Silicon (Metal 3).
- **New-tab live scene:** `index.html?ambient`, untouched for **38 min** (about 19 tour laps).
- **Game:** Medium detail. An in-page driver every 20 s jumps to the next viewpoint, swims with strafing (sometimes with Faster), and presses G and P. The driver was fixed at T+7 because losing focus had sent the game to its menu; the game clock restarts there and covers **31 min**.
- Instruments: `performance.memory.usedJSHeapSize` (MB, as shown); draws per second from `GPUQueue.submit` counts; the worst `requestAnimationFrame` gap per minute. One sample per minute.
- **Not instrumented:** GPU memory (WebGPU exposes no counter).

## Post-Session Analysis
### Memory Trend
- New tab: 21.1–22.5 MB for the whole run, no upward trend (−4% from T+0).
- Game: 27.7–28.5 MB, no upward trend (±1.5%).
- GPU memory: **NOT ASSESSED** (no counter available).

### Stability Summary
- No crash, hang or device loss in either page. Both were still moving at the end (two screenshots 3 s apart differ).
- **The new-tab tour loops correctly.** This fixes the freeze after the first lap that code review had found. 19 laps were completed.
- **30 fps cap holds:** 29.3–30 draws/s for 38 min.
- **The new-tab scene never touched the game's quality keys** (`abyssal` and `abyssalLoad` stayed unset in its storage).
- Recurring 70–155 ms worst frames appeared during the run. A follow-up 90 s run of the new tab **alone** gave p99 10.3 ms, worst 10.4 ms, none over 50 ms. So the hitches came from the soak's two GPU-heavy pages contending, not from the game.
- Side finding: with both soak pages open, a third page's GPU request never answered and the game sat on "Diving…". **Fixed:** a 20 s timeout now leads to the fallback screen with the cause (verified: 21 s).

### Balance / Fatigue Summary
**NOT ASSESSED.** An automated driver can't judge fun. One objective signal was passed to the balance check: in 31 minutes from the viewpoints, the driver found 4 garden spots and 0 wonders (see `balance-check-progression-2026-11-17.md`).

### Issues Found
| Issue | Severity | Status |
|---|---|---|
| GPU request could wait forever with several WebGPU pages open | High (stuck loading screen) | Fixed: 20 s timeout and fallback |
| Background new tabs each kept a live world | Medium | Fixed: released after 20 s hidden |
| No wonders found from the hub in 31 min | Balance | Mitigated: first-dive hint |

## Verdict: PASS WITH CONCERNS (memory and stability)
No leak in the JS heap over 31–38 minutes, stable frame pacing, no crashes. The concerns: GPU memory was not measured; one machine only; balance/fatigue NOT ASSESSED. A 1-hour soak on a low-end or integrated-GPU machine is the next step.
